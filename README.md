# ClipClean

在本机视频中定位并删除一段固定广告。程序通过音频相关性粗定位，再用画面逐帧确认
边界；只有综合匹配分达到安全门槛时才会自动剪切，并且永远不会覆盖原视频。

## 日常使用（Windows 图形界面）

双击发布目录中的 `启动ClipClean.cmd`（或 `ClipClean-v0.3.0.exe`）：

1. 如果 `work\ad-reference.mp4` 已存在，程序会自动选中它；否则点击“制作基准”；
2. 把一个或多个待处理视频拖入窗口；
3. 确认输出目录，点击“开始处理”；
4. 新视频以 `原文件名_已去广告.mp4` 写入输出目录。

也可以直接把视频拖到 `ClipClean-v0.3.0.exe` 或 `启动ClipClean.cmd` 上，程序会打开并把这些视频
预先加入队列。

界面会记住广告基准和输出目录。批量处理始终显式使用 `audio-safe`，与当前试听通过的
策略一致；原视频不会被修改，已有同名输出也不会被覆盖。检测报告和四张边界预览收纳
在输出目录的 `_ClipClean处理记录` 中。每个任务还会保存一份完整 `.log`；失败时选中该行并
点击“打开结果”，会直接打开对应日志。

从 0.2.6 起，程序默认只在视频时长的 35%–65% 范围搜索广告起点，减少长视频的音频
扫描时间。命令行需要兼容广告位置不固定的视频时，可加 `--full-scan` 恢复全片搜索。

图形界面使用 Windows 自带的 WinForms，不需要额外安装 GUI 运行库。修改界面源码后可在
PowerShell 中运行 `./build-gui.ps1` 重新生成 `ClipClean-v0.3.0.exe`。
开发者要生成完整发布包时运行 `./build-release.ps1`；如果 FFmpeg 不在常见目录，先把
`FFMPEG_BIN` 设置为同时包含 `ffmpeg.exe` 和 `ffprobe.exe` 的 `bin` 目录。

## 给第一次使用的人

普通用户应下载 GitHub Release 页面里的 `ClipClean-0.3.0-windows-x64.zip`。解压后只需双击
`启动ClipClean.cmd`，不需要安装 Python；发布目录自带处理引擎和 FFmpeg。

第一次使用有两种方式：

1. 已经有纯广告基准时，在“广告基准”处选择它，然后把待处理视频拖入列表。
2. 只有一段包含广告的完整视频时，点击“制作基准”，填写广告开始和结束时间，工具会自动生成纯广告基准。

默认设置适合当前固定广告：只扫描视频中间 30%，广告开始前多删 3 帧、结束后多删 2 帧，
并保留 1 帧音画共同安全余量。设置区可以切换到自定义搜索范围、全片扫描，以及“更少切除”或
“更强清除”预设。更少切除可能留下广告画面或声音，更强清除会多牺牲少量正片画面。

广告位置范围只影响定位阶段速度，不影响最后整片重新编码时间。已知广告只会出现在更窄区间时，
可以使用自定义范围进一步减少定位时间；不确定时请保留默认范围或选择“扫描整段”。

所有结果都会写入输出目录，原视频不会被覆盖。失败任务会生成 `.log` 和 JSON 报告，报告中的
`cut.validation` 是程序是否真正验收通过的依据。

开发者也可以使用命令行调整同样的参数：`--search-start-ratio`、`--search-end-ratio`、
`--full-scan`、`--leading-guard-frames`、`--trailing-guard-frames` 和
`--safety-guard-frames`。`prepare-ad` 同时支持 `--start-time/--end-time` 和帧号参数。

## 自动回归测试

在项目目录运行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

测试会临时生成一段由 15fps 正片、30fps 广告和 20fps 正片组成的变帧率视频，调用真实
剪切流程，再逐帧确认广告画面为零、前后正片均存在且音视频时长通过校验。

## 环境

- Windows 10/11
- Python 3.11 或更高（已按 Python 3.13.3 验证）
- FFmpeg 和 FFprobe

程序会依次从系统 `PATH`、环境变量 `FFMPEG_BIN` 和常见目录中查找 FFmpeg。找不到时，
请把 `FFMPEG_BIN` 设置为包含 `ffmpeg.exe` 和 `ffprobe.exe` 的 `bin` 目录。

## 当前广告基准

最初的 `work\10月14日.mp4` 首尾包含正片，不能直接作为纯广告样本。已经确认其中广告
位于 `[13, 395)` 帧，并生成了精确的 `work\ad-reference.mp4`：24fps、382 帧、
15.916667 秒。

如需重新生成：

```powershell
.\.venv\Scripts\python.exe adskip.py prepare-ad `
  --source "work\10月14日.mp4" `
  --start-frame 13 `
  --end-frame 395 `
  --output "work\ad-reference.mp4"
```

## 检测与剪切

在项目目录打开 PowerShell：

```powershell
.\.venv\Scripts\python.exe adskip.py doctor

.\.venv\Scripts\python.exe adskip.py detect `
  --ad "work\ad-reference.mp4" `
  --video "work\10月14日(1).mp4" `
  --output "outputs\matches.json"

.\.venv\Scripts\python.exe adskip.py cut `
  --ad "work\ad-reference.mp4" `
  --video "work\10月14日(1).mp4" `
  --output "outputs\10月14日(1)_已去广告.mp4"
```

`cut` 会同时生成新视频、JSON 报告和四张边界预览。匹配分低于 `0.90` 或输出文件已经
存在时会停止，不会冒险剪切或覆盖文件。边界预览使用时间点快速定位；预览生成失败时
只会记录警告，不会再阻止已经验证通过的主视频输出。

剪切完成后还有一道输出验收门：程序会在接缝附近重新搜索广告画面，检查音视频尾差，
并检查接缝处是否出现疑似重复帧。广告残留、尾差过大或重复帧会使任务失败，报告中的
`cut.validation` 会记录相似度、尾差、接缝运动值和失败原因。

从 0.2.3 起，检测和正式剪切统一使用视频流时间戳。报告中的帧号只是把时间戳换算成的
检测流参考值，不再用于裁切原始视频。这样可避免变帧率视频中“平均帧号”和真实时间轴
不一致，导致音频已经删净但画面仍残留广告的问题。

从 0.2.5 起，输出验收使用 RGB 画面比较，避免不同颜色但相同亮度的画面造成误报。验收
失败时只删除临时文件并返回错误，不会把可疑结果改名为最终输出文件。

从 0.2.6 起，音频安全模式会在画面广告起点前增加三帧、终点后增加两帧保护，并分别
检查输出接缝两侧是否残留广告的开头或结尾画面。即使只剩一两帧，也不会再依靠整段广告
相似度而误判为通过。

从 0.2.7 起，默认 `--mode audio-safe` 会取广告音频、画面保护区间的并集，并让视频和
音频删除完全相同的区间。程序不再在接缝中插入静音，只使用 2ms 淡出/淡入防止爆音。
代价是必要时会多删除接缝两侧各约一帧画面，但后半段音画同步不变。需要完全不加保护
时可显式使用 `--mode precise`。

视频和音频分别确定边界。当前固定广告的音频在广告画面出现前已经开始，因此
`work\ad-reference.profile.json` 记录了独立的音频边界校准值。程序会自动加载与广告
基准同名的 `.profile.json`，使用校准后的音频区间参与共同安全边界计算，并在接缝两侧
使用 2ms 淡出/淡入。报告中的 `audio_seam_silence` 应始终为 `0`。

从 0.3.0 起，图形界面支持制作广告基准、搜索范围和切除余量设置；发布包自带独立处理引擎
和 FFmpeg，普通用户无需安装 Python。

报告字段：

- `start`：广告第一帧所在时间附近；
- `end`：广告结束后的第一个保留位置；
- `start_frame`：检测流中的参考帧号，仅供诊断；
- `end_frame_exclusive`：检测流中的结束参考帧号，仅供诊断；
- `audio_score`：音频匹配分数，越接近 1 越可靠。
- `video_score`：抽样画面的逐帧相似度；
- `combined_score`：音频与画面的综合置信分数。

真正的剪切边界由 `start` 和 `end` 时间戳决定；参考帧区间仍采用半开区间
`[start_frame, end_frame_exclusive)`。

用当前两段素材验证得到：画面广告位于 `1.166667s - 17.083333s`，对应 24fps 视频的
`[28, 410)` 帧。音频安全模式实际删除 `[25, 411)`，输出为 58 帧、2.416667 秒；
视频轨和音频轨时长完全一致。

## 当前限制

- 首版要求广告样本与目标视频都包含音轨。
- 变速、重新配音或大幅改变音高的广告可能无法可靠识别。
- 变帧率视频按原始视频流时间戳剪切并保留可变帧率，音频统一裁到画面终点。
- 每个视频当前只删除一次固定广告；同一视频中重复出现多次广告尚未支持。
- 当前输出为 H.264 CRF 18 和 AAC 192kbps，字幕流暂未复制。
